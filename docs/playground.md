# 游乐场与我的排班

成员与管理员底部导航为「工作台」「互动区」「我的排班」「游乐场」；管理员另有「安排排班」。超级管理员保持管理入口，不展示参与类入口。

「我的排班」中可切换「我的报名」「我的换班」，切离再返回时保留本次会话中最后打开的子页。报名、换班消息及已有深链接仍打开对应功能。

## 小工具

- 抽签：每行一项，最多 50 项；支持一次抽多项、抽中移出名单；同一次不重复。
- 幸运大转盘：2–12 个等概率选项，先随机确定结果再播放动画，指针与结果对应。
- 随机分组：2–50 人，人数尽量平均，每位只出现一次。
- 掷骰子：1–6 枚六面骰，展示各点数及总点数。
- 抛硬币：正反两面随机结果。

这些工具的输入和结果仅留在当前页面，刷新或离开工具后重置。随机数使用 Web Crypto，不新增依赖。

抽签、转盘和随机分组均支持「从员工选择」，可搜索、多选、全选。选择器仅展示启用员工与管理员的展示名称，本人追加「（我）」。重名通过用户编号区分，保留手动编辑入口。每项最多 80 字，选择员工后替换当前名单；转盘最多选 12 人，抽签/分组最多 50 人。

## 圣经版阿瓦隆：守望之旅

这是使用圣经意象作为原创背景的聚会游戏，角色为虚构设定。基础机制参考 [The Resistance: Avalon 规则](https://www.rulespal.com/resistance-avalon/rulebook)。不包含同机传阅模式；每位玩家使用自己的时禾账号、手机或浏览器参与。

1. 游乐场 → 圣经版阿瓦隆 → 创建房间，将六位房间号发给朋友。
2. 5–10 位成员加入并准备后，房主开始。各自私密查看身份并确认；切到后台或失去窗口焦点时会隐藏身份弹窗。
3. 队长轮流组队，全员秘密投票，超过半数赞成才通过。平票否决，连续五次否决后暗影获胜。
4. 队员各提交一张任务牌，光明只能支持，暗影可支持或破坏。任务牌不可修改，只公开聚合票数。7–10 人的第四次使命需两张破坏才失败，其余一次即可。
5. 三次使命失败暗影胜利；三次成功后，由试探者最终指认先知，猜对暗影胜利，否则光明胜利。结束后公开角色，房主可再开一局。

光明角色为先知、守望者、同行者；暗影角色为试探者、迷惑者、潜伏者。先知知道暗影成员；守望者知道先知和迷惑者两名候选但无法区分；暗影互相知晓。没有额外角色或扩展规则。

房间状态保存在服务器 SQLite 中，进入页面每 5 秒同步，切回前台立即同步。刷新、短暂断线、切换主页面后可回到当前房间。一个账号同时加入一个房间。房主解散会关闭房间；对局中成员退出会终止本局。房间 24 小时无操作后失效；投票、任务和身份确认没有强制倒计时。讨论通过当面或语音进行，本版不附带房间聊天。

## 接口与隐私

三种游戏共用 `/api/playground/rooms`，必须登录；超级管理员不可参与。`GET /current` 恢复当前房间，`POST /` 创建（`game` 为 `avalon`、`undercover` 或 `uno`），`POST /join` 加入，`GET /:id` 同步，`POST /:id/actions` 操作。一个账号在所有游戏中合计只能加入一个房间，跨游戏时可返回已有房间或退出后再创建。

- 创建与加入使用当前登录用户；读取和操作必须属于该房间，房主也不能查看他人的身份。
- 身份与任务牌只存于服务器；响应通过显式字段列表裁剪，仅返回本人角色及其可知信息。结束前不返回其他人的角色；投票齐全后才公开每人的赞成/反对，任务牌始终只返回汇总。
- 服务端校验队长、房主、试探者、队员权限，以及光明不能破坏的规则；不信任前端按钮或上传的角色信息。
- 同一阶段每人只能投票/提交一次，阶段编号防止过期操作影响后续轮次。事务保护结算，重复推进不会跳过阶段。
- 返回 `Cache-Control: no-store`；日志不记录请求体、角色或任务牌。
- 数据库版本 38 包含 `playground_rooms`、`playground_members`、`playground_records`、`playground_record_members` 四张表，以及游戏记录的房主编号，不改动排班或待办数据。v37 记录按首位入房者补齐房主（此前房主首先入房，且不能转移房主）。
- 员工名单接口 `/api/playground/people` 仅返回 `id` 和展示名称 `name`；不返回真实姓名映射、工号、联系方式或账号安全字段。

## 圣经版谁是卧底：同词异心

4–10 人联机。4–6 人 1 名卧底，7–10 人 2 名；词组为原创整理的圣经人物、地点、物件相近词，不使用第三方词库。玩家只领取自己的词，开局不知阵营；服务器不返回其他词或词库。

领取后轮流文字描述（最多 120 字），也可口头描述后确认。接口禁止在描述中直接写出自己的词。全体在场成员秘密投票，不能投自己，提交后不可修改；最高票者出局并公开阵营。平票最高者加赛描述再投一次，再次平票则无人出局。出局者只能旁观。卧底全部出局平民胜；卧底人数不少于平民则卧底胜。结束时揭示全部词语和阵营。不包含白板角色。

## 圣经版 UNO：彩约对局

2–10 人联机，108 张基础牌，每人 7 张。牌面原创，颜色使用葡萄紫、麦穗金、橄榄绿、溪水蓝。按同色、数字或功能出牌；支持跳过、反转、加二、换色、加四；两人反转相当于跳过。下一位直接抽取惩罚牌并跳过，不叠加。

本版家庭规则：开局翻数字牌，随机先手。+4 由服务器强制校验没有同色手牌，省去质疑流程；剩两张时需在出牌前勾选 UNO，否则自动补两张。抽一张后只能出新抽到的牌，或结束回合；不可连续抽或改出旧牌。出完即获胜，不累计积分。牌堆耗尽时洗回弃牌并保留顶牌。

每位玩家仅能读取自己的手牌，其他人只公开牌数。服务端决定回合、发牌和可出条件；阶段号防重，手牌归属、选色与功能均由服务端验证。基础机制参考 [Mattel UNO 说明书](https://service.mattel.com/instruction_sheets/41001-0925-2L.pdf)，未使用官方牌面或商标设计。

## 游戏记录

游乐场首页与游戏顶部均提供「游戏记录」。从具体游戏进入时默认筛选该游戏，从游乐场首页进入时默认展示全部游戏，仍可手动切换筛选。三种游戏开局后，正常完成、房主解散、成员退出或长时间无操作过期都会保存记录；未开始的等待房间不保存。重新开始会创建下一局，保留上一局；解散和房间过期不删除既有记录。

记录仅本局参与者可查看，管理员不具备旁观权限。支持按游戏筛选与分页，保存开始/结束时间、房间号、参与人展示名称和结果。阿瓦隆记录角色、组队投票及使命结果；卧底记录结束时揭示的词语、阵营、描述和投票；UNO 记录每人的剩牌数及最近最多 500 条公开动作，不保存其他人的隐藏手牌到公开记录。

房主在记录详情中可点击「删除记录」，须再次确认。删除后所有参与者均无法查看，且不可恢复；其他参与者不显示按钮，管理员或超级管理员也不能越权删除。

记录接口为 `GET /api/playground/records` 与 `GET /api/playground/records/:id`，要求登录并验证记录成员关系，返回禁止缓存。`DELETE /api/playground/records/:id` 仅允许本局房主，删除时同时清理记录成员关系。进行中不产生可见记录，部分投票和单人任务牌不会进入公开记录。

## 验证

`npm test` 运行后端全量测试，其中阿瓦隆测试覆盖人数、身份隔离、权限、并发投票、五次否决、任务牌约束、第四次使命规则、最终指认、退出与过期。

`npm run test:h5` 验证名单输入、抽签去重、分组均衡和随机数范围。`npm run build --workspace h5 -- --configLoader runner` 构建前端。
