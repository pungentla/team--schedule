# 日历排班与分享

工作台「查看 → 日历看板」跨周期展示生效安排，不必选择排班周期。管理员也可从「安排排班 → 日历排班 → 打开日历看板」进入，超级管理员可用此入口。

管理员点「新增排班」或日期弹窗中的「新增工作」，选择过去或将来的日期、启用的班次、工作与人员，确认后立即生效，无需员工报名。主副工作必须各选一人；普通工作可选多人，支持同一班次承担不同工作。同一天、同一班次、同一工作已存在周期安排或日历安排时拒绝重复新增。日历新增的工作可在日期弹窗移除，需二次确认，增删均记入审计日志。该入口不修改周期生效版本。

日历安排独立存储，不自动创建报名周期。本人和团队近期安排、概览及排班提醒包含日历安排，历史安排也参与之后生成排班的轮转参考。当前自助换班沿用周期排班流程，独立日历安排由管理员管理。

生效排班的日期弹窗和列表日期卡片均有分享入口；日历看板的日期弹窗同样支持分享。可复制包含排班文字的链接，或生成 1440 像素宽的 PNG 图片，图片附二维码。分享图是生成时的快照，链接登录后读取最新生效安排；未发布草稿不提供分享入口。图片过长时提示改用链接，不悄悄省略人员。分享内容使用展示名称，不包含工号、账号凭据或报名信息。

链接格式 `/?scheduleDate=YYYY-MM-DD&schedulePeriod=ID` 定位具体周期当天；省略周期时展示该日所有生效安排（含日历新增安排）。未登录先登录，登录后自动打开日期弹窗。链接不授予额外权限，已删除周期仍由原接口返回不存在。

数据库 v43 新增 `calendar_works` 和 `calendar_people`，不改变已有周期、排班、禾穗或成绩。接口：登录用户 `GET /api/schedule/calendar?startDate=...&endDate=...`，一次最多 62 天；管理员可 `GET /api/schedule/calendar/people`、`POST /api/schedule/calendar`、`DELETE /api/schedule/calendar/:id`。名单接口只返回展示名和编号。
