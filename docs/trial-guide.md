# 给同事试用的操作指南

目标：让同事在手机上打开小程序、用邀请码注册、自己排班看排班，**不花钱、不备案**。

---

## 先搞清一个前提

微信小程序的**体验版**和**正式版**一样，`wx.request` 只允许访问**合法的 HTTPS 域名**。

这意味着：

| 你想用的地址 | 能不能用 |
|---|---|
| `http://127.0.0.1:3000` | ❌ 只在开发者工具里能用 |
| `http://192.168.1.5:3000` | ❌ 手机端会被拦截 |
| `https://xxx.trycloudflare.com` | ✅ 可以用 |

所以**必须给你的本地后端套一层 HTTPS 外壳**。下面给两条路。

---

## 方案 A：真机调试（最快，0 配置）

适合：**同事就坐在你旁边**，或者你自己先验证功能。

### 步骤

1. 电脑启动后端

```bash
cd backend && npm run dev
```

2. 看启动日志里的局域网地址，例如：

```
局域网访问: http://192.168.1.5:3000/api   (真机调试用这个)
```

3. 开发者工具点工具栏 **「真机调试」** → 手机扫码
4. 在真机调试的悬浮面板里，**打开「不校验合法域名」**
5. 在小程序登录页点顶部地址栏「切换」，填 `192.168.1.5:3000`
6. 点「保存并测试连接」→ 显示连接成功即可登录

### 限制

- 同事手机必须**和你在同一个 WiFi**
- 你的电脑必须一直开着，后端不能停
- 每人每次都要走一遍真机调试（不能各自扫码独立用）

> 如果只是**你自己先跑通**，用这个方案 5 分钟就能验证。

---

## 方案 B：内网穿透 + 体验版（推荐，同事可独立使用）

适合：同事分散、或想让他们**随时自己打开用**。

体验版一旦上传，同事扫码即可打开，**不需要你的电脑开着**——但后端仍然要在你的电脑上跑，所以穿透隧道要保持。

### 步骤 1：启动后端 + 穿透

选一个工具，任选其一：

#### 选项 1：Cloudflare Tunnel（免费、稳定、无需注册账号也能临时用）

```bash
# macOS
brew install cloudflared
# Windows: 从 https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/ 下载

# 临时隧道（无需登录，会生成一个随机 https 域名）
cloudflared tunnel --url http://127.0.0.1:3000
```

输出里会有一行：

```
+--------------------------------------------------------------------------------------------+
|  Your quick Tunnel has been created! Visit it at:                                          |
|  https://random-words-1234.trycloudflare.com                                               |
+--------------------------------------------------------------------------------------------+
```

这个 https 地址就是你的临时公网入口。

> ⚠️ 临时隧道**每次重启地址都会变**，变了就要重新在小程序里改地址。如果要固定地址，需要 Cloudflare 账号 + 自己的域名（免费版够用）。

#### 选项 2：ngrok

```bash
ngrok http 3000
```

同样会给出 `https://xxxx.ngrok-free.app`。

> 免费版每次重启地址也变，且首次访问会有拦截页（对 API 可能有影响）。

#### 选项 3：花生壳 / 贝锐（国内，免费版有固定二级域名）

国内访问更稳定，但免费版有带宽和流量限制。

### 步骤 2：在小程序里填这个 https 地址

登录页 → 顶部「切换」→ 填入穿透地址（如 `https://random-words-1234.trycloudflare.com`）→ 保存并测试连接。

**注意**：`normalizeUrl` 对 `https://` 开头且无端口的地址会补 `:443`。如果你填的是穿透域名，可以**直接填完整地址**，它会正确识别。

> 如果填完提示连不上，先在自己电脑浏览器打开 `https://你的域名/api/health` 看是否返回 `{"data":{"ok":true...}}`。

### 步骤 3：上传体验版

1. 开发者工具点 **「上传」**
2. 填版本号（如 `1.0.0`）和备注
3. 到 [小程序后台](https://mp.weixin.qq.com) → **管理 → 版本管理** → 找到刚上传的版本 → **设为体验版**
4. 在 **成员管理 → 体验成员** 里，添加同事的微信号
5. 把体验版二维码发给同事，扫码打开

### 步骤 4：同事注册

1. 同事打开小程序 → 点「用邀请码注册」
2. 邀请码填 `TEAM2025`（或你在后台生成的）
3. 自己设工号、姓名、密码
4. 登录后即可报名、看排班

## 关键：穿透地址变了怎么办

这是方案 B 最容易踩的坑。临时隧道重启就换域名，同事那边会突然全部连不上。

**三种应对**：

| 做法 | 说明 |
|---|---|
| **固定二级域名** | Cloudflare 账号 + 自有域名，配置 `cloudflared tunnel` 持久隧道，地址永久固定（推荐） |
| **花生壳免费版** | 给固定二级域名，但需要实名 |
| **接受变化** | 每次变了自己在小程序里改一下地址，同事那边不用改（地址存在各自本地，需要每人改一次） |

> 说实话：如果打算让同事用超过两周，**建议直接买个 ¥50/年的域名 + Cloudflare 免费隧道**，把地址固定下来。反复改地址很磨人。

---

## 试用期间必须注意的两件事

### 1. 数据安全

穿透相当于把你的电脑暴露在公网。当前后端**没有限流、没有 IP 白名单**。虽然要登录才能用，但仍建议：

- 穿透地址**不要公开发到群里**，只发给用的人
- 试用结束后及时关掉隧道
- 不要用真实敏感信息注册测试账号

### 2. 电脑关机 = 服务停止

方案 B 里后端跑在你的电脑上。**你合上笔记本，同事就用不了**。

如果要长期稳定，还是得往服务器上搬（见 `docs/deployment.md`）。

- [ ] 后端已启动，`http://127.0.0.1:3000/api/health` 返回 ok
- [ ] 穿透隧道已开，`https://你的域名/api/health` 在**手机浏览器**里能打开
- [ ] 小程序登录页保存的地址是**https 开头**
- [ ] 已上传并设为体验版
- [ ] 同事微信号已加入「体验成员」
- [ ] 已把邀请码发给同事

## 用 Docker 跑（推荐，省去装环境）

### 启动

```bash
# 在仓库根目录（不是 backend 目录）
docker compose up -d --build

# 首次灌演示数据
docker compose exec backend node scripts/seed.js

# 看日志
docker compose logs -f backend
```

起来后：

- 后端：`http://127.0.0.1:3000/api/health`
- H5 预览：`http://127.0.0.1:8080`（可直接在浏览器验收，含管理后台）

### 常用操作

```bash
docker compose ps                  # 看状态（应为 healthy）
docker compose restart backend     # 重启后端
docker compose down                # 停止（数据保留）
docker compose down -v             # 停止并清空数据
```

数据库存在命名卷 `teamshift-data`，`down` 不会丢数据。

### 端口被占用怎么办

如果报 `bind: address already in use`，说明 3000 端口已被占用（常见于本地 `npm run dev` 还开着）：

```bash
# 先停掉本地后端
lsof -ti:3000 | xargs kill -9        # macOS / Linux
# Windows:
netstat -ano | findstr :3000         # 找到 PID 后 taskkill /PID <pid> /F

# 或者改 compose 端口映射，用 3001
```

改端口的话，编辑 `docker-compose.yml`：

```yaml
ports:
  - "3001:3000"     # 左边是宿主机端口，改成空闲的
```

穿透时记得同步改端口：`cloudflared tunnel --url http://127.0.0.1:3001`。

### 构建说明

`Dockerfile` 位于 `backend/`，但**构建上下文是仓库根目录**（因为本仓库用 npm workspaces，`package-lock.json` 在根上）。`docker-compose.yml` 已配好，直接用 `docker compose up` 即可，无需手动 build。

单独构建：

```bash
docker build -f backend/Dockerfile -t teamshift-backend .
```
